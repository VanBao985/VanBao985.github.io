# College Memories — vanbao985.github.io

A photo gallery for student life, built as a React + Vite single-page app and
hosted on GitHub Pages. Photos live in **public Google Drive folders**, not in
this repo.

## How it works

There is no server and no database. The build reads your public Drive folders,
writes the file list into a static JSON, and the app renders from that.

```
npm run build
  ├─ npm run sync:drive   → read Drive folders → public/data/drive-photos.json
  └─ vite build           → bundle into dist/
```

Visitors never talk to Google's API — they load one small JSON file, and the
images themselves come straight from Drive's CDN.

**Why the listing happens at build time:** Google's `embeddedfolderview`
endpoint sends no CORS header, so a browser cannot fetch it. Node can. The
trade-off is that **new photos in Drive only appear after a rebuild**.

## Adding a folder

Edit [`src/data/drive-folders.js`](src/data/drive-folders.js):

```js
export const DRIVE_FOLDERS = [
  { id: '1__Z22t7OTdcVKMvFAZak2Kc2Qy6TNxWu', name: 'Graduation' },
  { id: '<folder id>',                        name: 'Freshman Year' },
];
```

The `id` is the part after `drive.google.com/drive/folders/`. Each folder must
be shared as **"Anyone with the link"**. The order here is the order the filter
chips appear in, and chips only show once there is more than one folder. Totals
and per-folder counts are computed automatically.

Subfolders are ignored on purpose — to include one, list it explicitly.

Then redeploy (push to `main`, or run the workflow manually).

## Routes

Routing happens on the client — there is only one HTML file.

| Route | Screen | Access |
|---|---|---|
| `/gallery` | The gallery — the entry point | public |
| `/invite?to=Name` | A guest's personalised invitation | public |
| `/invite-maker` | Create and download invitations | admin |
| `/login` | Paste a GitHub token to sign in | public |
| `/` and anything else | Not-found screen | public |

The site root `/` is deliberately not a route. Share the `/gallery` URL.

## Invitations

Sign in at `/login`, open **Invites**, type a friend's name and download their
card as a PNG. Downloading also reveals a link like `/invite?to=Minh` — send
that over and they see the same card, plus a button into the gallery.

### Using your own design

The card is an image in `public/invite/` with the guest's name drawn on top,
so your design keeps its own fonts, photo and illustrations.

1. Export your design **without a guest name**, leaving that area blank.
2. Save it to `public/invite/` (PNG or SVG).
3. In [`src/data/invitation.js`](src/data/invitation.js), point `template` at
   it, set `width`/`height` to its real pixel size, and nudge
   `guestName.x` / `.y` until the name lands where you want.

`public/invite/template.svg` is a placeholder demo — replace it.

The guest's name travels **inside the link**, so nothing is stored anywhere
and no rebuild is needed to hand out a new invitation.

**About the sign-in:** it asks GitHub who the token belongs to and requires it
to be your account, so it cannot be faked by editing the bundle. The token
needs **no repository permissions at all**. Be clear-eyed though — nothing
secret sits behind the gate; it keeps the tab out of a casual visitor's way
rather than protecting data.

### How deep links survive GitHub Pages

Pages serves static files and knows nothing about client-side routes, so
`/gallery` would normally 404. The build copies `dist/index.html` to
`dist/404.html`; Pages serves that for unknown paths, the app boots, and
react-router renders the right screen. This keeps URLs clean (`/gallery`,
not `/#/gallery`).

## Project structure

```
├── index.html                   # The only HTML entry (React mounts at #root)
├── vite.config.js               # Build config + the 404.html SPA fallback plugin
├── scripts/fetch-drive-photos.mjs  # Build-time Drive folder sync
├── .github/workflows/deploy.yml # Build + deploy to GitHub Pages
├── public/
│   ├── .nojekyll                # Disable Jekyll on Pages
│   └── data/drive-photos.json   # Generated by the sync script
└── src/
    ├── main.jsx                 # React bootstrap (BrowserRouter)
    ├── App.jsx                  # Route table
    ├── pages/                   # Gallery, NotFound
    ├── components/              # Layout, Header, Footer, Hero,
    │                            # Achievements, StatCounter, PhotoCarousel
    ├── data/drive-folders.js    # Which Drive folders to show
    ├── data/achievements.js     # The animated highlights band
    ├── lib/drive.js             # Drive image URLs
    ├── lib/assets.js            # Resolves public/ asset URLs
    └── styles/main.css          # Design tokens + all styling
```

## Local development

```bash
npm install
npm run dev        # http://localhost:5173/gallery
npm run sync:drive # refresh the photo list from Drive
npm run build      # production build into dist/
npm run preview    # serve dist/ locally on :4173
```

## Caveats worth knowing

- Both Drive endpoints used here (`embeddedfolderview` for listing,
  `thumbnail?id=` for images) are **undocumented**. They work today but Google
  could change them without notice.
- Make a folder private and its photos disappear from the site.
- Drive gives us only file names — no dates, albums or descriptions. Richer
  metadata would need a separate mapping file.
- `public/data/drive-photos.json` is regenerated by every build, so it shows up
  as modified in `git status` after building locally.
- The visit counter uses **counterapi.dev**, a free keyless service. Every page
  view sends a request there, and since the endpoint sits in the public bundle
  anyone could inflate the number — it is decoration, not analytics. If the
  service goes down the counter simply disappears.
- The dark palette is duplicated in `main.css` (once for the system preference,
  once for the explicit `data-theme` choice). Keep both copies in sync.

## Deployment

Push to `main` — the `deploy.yml` workflow builds and publishes `dist/`. The
repo's Pages source must be set to **GitHub Actions** (Settings → Pages →
Source). Live at **https://vanbao985.github.io/gallery**.
